# Spot Check, 50 Reports: Instructions and Context

## What to Do

Open `spotcheck_50_blind.csv`. Each row pairs two things from the same accident report:

- a **finding** (`finding_text`): a cause that the NTSB investigators coded for this accident, taken from the structured findings field;
- a **node** (`factor_type`, `cause_role`, `trigger`): one step that the model extracted from the narrative, with the phrase it quoted.

Every finding of a report is listed against every node of that report, so most rows are 0. For each row, answer one question: **does this node describe the same cause as this finding?**

- Write **1** if a reader would say "yes, the model found this NTSB cause". The wording does not have to match; the meaning does.
- Write **0** if the node is a different cause, or only a consequence of the finding (an impact, an injury), or merely related to it.
- Usually one node per finding is a 1, sometimes two, sometimes none (the model missed the finding).
- Fill every row. `annotator_note` is optional; use it for doubtful cases.
- Whether the narrative mentions the NTSB is irrelevant.

### Example (record 20011101X02178_1, balloon hard landing; finding: DESCENT (EXCESSIVE))

| node | factor type | quoted phrase | annotator_match |
|---|---|---|---|
| 0 | ADVERSE_WIND_CONDITION | winds starting to increase varying greatly in direction | 0, a different cause |
| 1 | UNSUITABLE_TERRAIN_FOR_FORCED_LANDING | landing sites were minimal | 0 |
| 2 | CONTROL_INPUT_IMPROPER | pilot's excessive descent rate during the landing approach | **1**, same cause |
| 3 | GROUND_IMPACT | balloon subsequently impacted the ground hard | 0, a consequence |
| 4 | INJURY_OR_FATALITY | passengers sustained injuries | 0 |

Below, each record gives the narrative, its findings and its nodes, so the rows of the sheet can be judged in context.
