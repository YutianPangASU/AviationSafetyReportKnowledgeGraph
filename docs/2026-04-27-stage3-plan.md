## Output we need to produce

For each CICTT category C with ≥ 50 records, a directed weighted DAG `G_C` over the 42-event vocabulary where each edge `(X → Y)` carries:

- `direction_score` ∈ [0, 1] — confidence that X causes Y rather than vice versa
- `support_count` — number of accidents in C contributing the triple
- `llm_prior` — Vashishtha-style temporal/causal-order judgment from the LLM
- `bootstrap_stability` — fraction of bootstrap resamples preserving the edge
- `cause_role_distribution` — share of supporting events flagged primary / contributing

`G_C` is what Stage 4 inputs. The 42 nodes are fixed across categories (so cross-category bridge edges are well-defined later); only the edge set + weights vary.

## Pieces with effort estimates (~1 week engineering total)

### 1. Per-category co-occurrence + temporal precedence matrices  ·  ~1 day  ·  not started

**Output:** for each category `C`, a 42×42 matrix `M_C[i, j]` = number of accidents in C where event-type `i` precedes event-type `j` (extracted from per-narrative `PRECEDES` / `CAUSES` / `TRIGGERS` edges, plus inferred precedence from `seq_of_events.seq_event_no` ordering for Pre2008 records).

**Deliverable:** `event_extraction/scripts/build_precedence_matrices.py` →
- `event_extraction/out/aggregate_kg/per_category_precedence/{cat}.npy` (42×42 numpy array)
- `event_extraction/out/aggregate_kg/per_category_precedence/{cat}.json` (axis labels + metadata)

**Validation:** sanity-check against the partial-run aggregate edge CSVs (e.g. for LOC-I, the (CONTROL_INPUT_IMPROPER, GROUND_IMPACT) cell should match `aggregate_kg.summary.md`'s top-edge count).

**Notes:** dedup edges within an accident; ignore self-loops; weight extraction-edge precedence (1.0) higher than inferred from `seq_of_events` (0.5).

### 2. Vashishtha-style triplet causal-order prompting  ·  ~2 days  ·  not started

**Method:** Vashishtha et al., ICLR 2025 — for each triple of event types `(a, b, c)` in a category, ask the LLM "in an aviation accident in category C, which of these typically comes first / which causes which?" Aggregate the partial orderings into a global ranking. Use this as a *causal-order prior*, not a direct edge prediction.

**Implementation choice:**
- Use the locally-running Qwen3.6-35B-A3B (vLLM) for budget reasons — it's already loaded and serves OpenAI-compatible JSON
- Constrained generation via `guided_json` so each triple-question returns `{"order": ["a", "b", "c"], "confidence": 0.x}` deterministically
- 42 event types × 42×41×40/6 triples = ~11,480 triples per category. Filter to triples that have ≥ N supporting accidents in the category to avoid asking about pairs that never co-occur. Realistic LLM-call count: ~500–2,000 per category.
- Concurrency 16, ~10 calls/s → ~3 min per category.

**Deliverable:** `event_extraction/scripts/llm_causal_order.py` →
- `event_extraction/out/aggregate_kg/per_category_llm_order/{cat}.json` — list of `{triple, order, confidence}` records
- Aggregate function that produces a 42-element `topological_score` per category from those records

**Validation:**
- On LOC-I: the LLM-derived ranking should put `DECISION_INAPPROPRIATE` and `ICING_ENCOUNTER` upstream of `STRUCTURAL_OVERLOAD`, and `STRUCTURAL_OVERLOAD` upstream of `GROUND_IMPACT`. If it doesn't, the prompt is wrong.
- Cross-model ablation flagged in the design critique (root 2 from the v3 redesign): re-run a subset with a different model family (e.g. an OpenAI API call for ~50 triples) and report Kendall's τ. **This is the LLM-circularity-mitigation step.** Do not skip it; it is the single most defensible robustness check the paper can carry.

**Reference:** Vashishtha, A. et al. *Causal Order: The Key to Leveraging Imperfect Experts in Causal Inference.* ICLR 2025. PDF in [paper/CAUSAL ORDER- THE KEY TO LEVERAGING IMPERFECT EXPERTS IN CAUSAL INFERENCE.pdf](../paper/CAUSAL%20ORDER-%20THE%20KEY%20TO%20LEVERAGING%20IMPERFECT%20EXPERTS%20IN%20CAUSAL%20INFERENCE.pdf).

### 3. Laplacian similarity prior  ·  ~2 days  ·  not started

**Method:** Zhang et al., NeurIPS CaLM 2024 — build a similarity matrix over event types from the LLM's pairwise judgments, compute its graph Laplacian, and use the Laplacian eigenstructure as a soft prior favoring edges within "tight" subgraph clusters and against edges that cross cluster boundaries.

**Implementation:**
- Reuse the LLM-pairwise output from piece 2 to build a 42×42 similarity matrix `S` per category
- Compute `L = D - S` (graph Laplacian) and its eigendecomposition
- The top-k eigenvectors give a low-dim embedding; pairwise distances in that embedding give the Laplacian prior on edge presence

**Deliverable:** `event_extraction/scripts/laplacian_prior.py` →
- `event_extraction/out/aggregate_kg/per_category_laplacian/{cat}.npy` — 42×42 prior matrix
- A small notebook entry sanity-checking that semantically related events (e.g. `STALL` ~ `LOSS_OF_CONTROL_INFLIGHT`) embed near each other

**Assumption audit (from the design critique):** the SCM assumptions (linearity, additive noise) that Zhang et al. require may not hold for aviation — the paper should explicitly note where the assumption is broken and what the consequence is for edge weights.

**Reference:** Zhang, Q. et al. *Leveraging LLM-Generated Structural Prior for Causal Inference with Concurrent Causes.* NeurIPS CaLM Workshop 2024. PDF in [paper/Leveraging LLM-Generated Structural Prior for Causal Inference with Concurrent Causes.pdf](../paper/Leveraging%20LLM-Generated%20Structural%20Prior%20for%20Causal%20Inference%20with%20Concurrent%20Causes.pdf).

### 4. PC algorithm with LLM-prior + Laplacian seeding  ·  ~2 days  ·  not started

**Method:** Constraint-based causal discovery (Spirtes-Glymour-Scheines PC algorithm) using the per-narrative event sequences as "samples." Seed the skeleton with the union of edges that pass any of:
- support_count ≥ threshold from piece 1
- LLM ordering confidence ≥ threshold from piece 2
- Laplacian prior weight ≥ threshold from piece 3

Then prune via conditional-independence tests on the per-narrative data.

**Library:** `causal-learn` (https://github.com/py-why/causal-learn) — pure Python, has PC + GES + LiNGAM + bootstrap utilities, takes binary or categorical data.

**Data prep:** for each accident in category C, build a binary 42-vector indicating which event types appeared. Run PC on the resulting matrix.

**Output:** CPDAG — a graph where some edges are oriented (the LLM prior helped resolve them) and some are bidirectional (data alone can't decide). Resolve bidirectional edges by majority of LLM-order vote.

**Deliverable:** `event_extraction/scripts/run_pc_per_category.py` →
- `event_extraction/out/aggregate_kg/per_category_dag/{cat}.gpickle` — final per-category DAG
- `event_extraction/out/aggregate_kg/per_category_dag/{cat}.csv` — `src,dst,weight,llm_prior,support_count,bootstrap_stability`

**Validation:** the LOC-I DAG should reproduce the design's flagship causal chain `DECISION_INAPPROPRIATE → CONTROL_INPUT_IMPROPER → STRUCTURAL_OVERLOAD → AIRFRAME_FAILURE → GROUND_IMPACT` from case-9 walkthrough in the v3 redesign doc. If it doesn't, debug here before scaling.

**No-LLM-prior ablation (mandatory per design critique):** rerun PC on each category with no priors at all, just the data. Save as `{cat}_no_prior.gpickle`. The paper baseline is the delta between LLM-prior-on and LLM-prior-off — that isolates the LLM contribution from the data contribution.

### 5. Bootstrap stability + edge-confidence scoring  ·  ~1 day  ·  not started

**Method:** for each category, resample 80% of accidents 100 times, rerun PC each time, count for every edge how many bootstraps preserve it. That's the `bootstrap_stability` weight.

**Deliverable:** integrated into piece 4's output CSV. Add a `bootstrap_stability` column (∈ [0, 1]).

**Note:** at 100 bootstraps × ~25 categories, the LLM triplet-prompting must NOT be re-run per bootstrap — only the PC algorithm is. The LLM prior is fixed per category. Use the same prior across all bootstraps for that category.

### 6. Per-category DAG visualisation  ·  ~1 day  ·  reuses [viz_kg.py](../event_extraction/scripts/viz_kg.py)

**Method:** add a new mode to [viz_kg.py](../event_extraction/scripts/viz_kg.py) that takes a per-category DAG and renders it with edge weights. Existing code already handles per-category subgraphs from CSVs — we just need a slightly different CSV schema that includes `weight` / `bootstrap_stability` instead of (or alongside) raw `count`.

**Deliverable:**
- `--dag-mode` flag on [viz_kg.py](../event_extraction/scripts/viz_kg.py) that reads `per_category_dag/{cat}.csv` instead of `per_category/{cat}.csv`
- Edge thickness scales by `bootstrap_stability`
- Edge opacity scales by `direction_score`
- Edge color stays per-edge-type
- Tooltip shows `support_count`, `llm_prior`, `bootstrap_stability` separately
- New top-level [index.html](../event_extraction/out/aggregate_kg/html/index.html) section: "Layer-2 causal DAGs"

### 7. Validation against published HFACS / expert review  ·  open-ended  ·  not started

**Three options for ground truth, ordered by feasibility:**

1. **Published HFACS analyses of high-profile accidents** (Colgan Air 3407, AF447, Asiana 214) — manually transcribe the published HFACS chain and check whether our LOC-I DAG reproduces the same edges with high stability. ~1 day per accident, total ~3-5 days for 5 accidents.
2. **NTSB structured `Findings` cause-flagged ordering** — for accidents with multiple `Cause_Factor='C'` findings, the `seq_event_no` order gives a partial-order target. Compare per-narrative edge ordering against this. Already feasible with the joined data; ~1 day.
3. **Independent expert annotation** — recruit 1-2 aviation safety domain experts, have them annotate ~50 candidate edges per category as causally valid / spurious / unclear. Inter-rater reliability ≥ 0.6 (Cohen's κ) is the threshold the design critique implied. ~weeks of calendar time depending on annotator availability.

**Recommendation:** start with (2) since it's free and immediate, then (1) for the paper's qualitative section, defer (3) for the camera-ready or follow-up.
